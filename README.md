## 1. 项目简介

「我不能被欺负」是一款帮助普通消费者快速找到官方投诉渠道的微信小程序。用户输入遇到的问题（如"快递被偷了"），系统通过本地关键词提取匹配相关场景，展示对应的投诉渠道、投诉话术与投诉流程，全程无需 AI、零 API 成本、可离线使用。

产品价值聚焦「找得到 → 用得上 → 走得对 → 跟得住」：

- **找得到**：122 条官方渠道结构化入库，关键词搜索直达对口部门。
- **用得上**：19 套高频场景话术（电话版 + 书面版），一键复制即用。
- **走得对**：每个渠道标注监管部门、受理范围、前置条件，避免找错门。
- **跟得住**：投诉跟进时间表提示每个节点的行动与升级路径。

## 2. 产品特性

- **本地关键词提取**：用户输入自然语言，自动提取核心关键词（正向最大匹配算法，330+ 词库）。
- **场景选项卡**：匹配到多个场景时，展示场景选项卡供用户点选，匹配度可视化。
- **纯本地搜索**：轻量索引 + 关键词提取 + 场景选项卡，无需后端、无需 AI、零 API 费用、可离线。
- **数据分片架构**：启动仅加载 56KB 轻量索引，详情按需加载 60KB 分片，单文件 ≤ 152KB，远低于 500KB 限制，支持扩展至 2000+ 条渠道。
- **权威内容**：122 条官方渠道、18 个高层级平台、19 套话术、90 部法律法规（条款级存储）、469 条同义词库。
- **全链路体验**：搜索 / 分类浏览 / 渠道详情 / 话术详情 / 收藏历史 / 工具箱（跟进时间表、热线速查、企业查询）/ 紧急入口（110/119/120/96110 二次确认）。

## 3. 技术架构

### 3.1 三层数据架构

```
Word 源文档 → Excel 维护层（人工可编辑） → JS 分片运行层（小程序加载）
                                          ↓
                          轻量索引（56KB，启动加载）+ 按需分片（60KB/片）
```

### 3.2 数据分片加载

```
启动时加载：channels_index.js（56KB，仅含 id/name/phone/tags/part_num）
搜索时：    用索引做名称匹配 + 关键词权重，不加载详情
点击详情：  按 part_num 按需加载 channels_part_N.js（60KB/片）
已加载分片：内存缓存，重复访问 < 10ms
扩展到 2000 条：自动新增分片，单文件永不超 500KB
```

### 3.3 搜索流程

```
用户输入自然语言 → 本地关键词提取（正向最大匹配）→ 场景匹配
  ├─ 1 个场景  → 直接进入渠道详情
  ├─ 2-5 场景  → 场景选项卡（用户点选）
  └─ 无匹配    → 轻量索引名称匹配搜索结果页
```

### 3.4 架构决策摘要（ADR）

| 决策 | 结论 | 详情 |
|------|------|------|
| 前端框架 | 微信小程序原生 | [TDD ADR-1] 性能/体积最优，多端 V3.0 评估 |
| 运行时数据 | JS 模块 + 轻量索引 + 分片 | [TDD ADR-2] require 100% 成功，规避 JSON 单文件限制 |
| 搜索方案 | 本地关键词提取 + 场景选项卡 | [TDD ADR-4] 零 API 成本、离线、可解释 |
| 状态管理 | 原生 globalData + 本地存储 | [TDD ADR-5] 当前复杂度低 |
| 后端（V2.0） | 微信云开发 | [TDD ADR-6] 免运维、按量付费 |

### 3.5 AI 可选接入（规划能力）

当前版本纯本地搜索零成本。架构预留 AI 接入抽象层（AIService），开发者可自选厂商（字节豆包 / 阿里通义千问 / OpenAI 等）、协议与模型，配置于 `miniprogram/data/config.json` 的 `ai` 字段，默认关闭，不影响存量逻辑。

## 5. 快速开始

### 5.1 环境要求

- Python 3.8+（`python-docx`、`openpyxl`、`jsonschema`、`tqdm`）
- 微信开发者工具（导入 `miniprogram/` 为小程序项目）

### 5.2 数据转换

```bash
pip install -r tools/requirements.txt

# 1. Word → Excel（提取数据，生成维护层）
python tools/convert.py --input "./source" --output "./data/我不能被欺负数据_维护版.xlsx" --mode extract

# 2. Excel → JS 分片数据（构建小程序运行层）
python tools/convert.py --input "./data/我不能被欺负数据_维护版.xlsx" --output "./miniprogram/data" --mode build

# 3. 一键全流程
python tools/convert.py --input "./source" --output "./miniprogram/data" --mode all

# 4. 仅校验数据
python tools/convert.py --input "./data/我不能被欺负数据_维护版.xlsx" --mode validate
```

### 5.3 数据校验与回归

```bash
node scripts/validate-data.js          # 数据一致性与质量校验
node scripts/search-hitrate-test.js    # 搜索命中率回归（50 个典型 query）
```

### 5.4 查看产品原型

用浏览器打开 `prototype/我不能被欺负_产品原型.html`，可体验完整交互流程。

## 6. 合规与备案

本小程序定位为**公益性生活消费维权信息工具**，仅提供官方投诉渠道、法律法规及投诉话术等公开信息查询服务。备案备注（可直接复制用于类目报备）见 [`docs/备案信息备注.md`](docs/备案信息备注.md)，核心要点：

- 不代理、不协助、不参与任何投诉或举报，不代用户提交材料；
- 倡导依法理性维权，鼓励优先企业官方客服 / 内部举报 / 反馈渠道协商；
- 虚假、恶意投诉造成后果的，由用户自行承担法律责任；
- 内容均来自政府公开渠道，标注验证日期与来源。

## 7. 规划中功能（Roadmap）

以下功能已纳入远期规划（当前版本 v1.5.0 暂不实现，数据模型预留扩展位），完整演进路线见 [`docs/我不能被欺负_产品远景规划.md`](docs/我不能被欺负_产品远景规划.md)：

- **支付与增值服务**（V3.0）：order/payment 能力预留，支撑未来合规增值场景（如深度报告、专家咨询），需通过合规评估后启动。
- **多端发布**（V3.0）：在微信小程序基础上评估 H5 / PC / APP 等多端形态，技术架构预留跨端适配（Taro / uni-app），当前仍以微信小程序为唯一优先平台。

以下为**短期规划（V1.5 体验完善版）**，计划于首版后 2-3 周落地（数据/内容侧增强，无需改架构），完整细则见 [`docs/我不能被欺负_产品需求文档PRD.md`](docs/我不能被欺负_产品需求文档PRD.md) 第 9.3 节、[`docs/我不能被欺负_产品远景规划.md`](docs/我不能被欺负_产品远景规划.md)：

- **媒体曝光路径**（V1.5）：新增「媒体曝光」第四条维权路径（舆论监督/社会监督），明确适用前提与合规边界，与官方渠道「先官方后媒体」衔接。
- **投诉所需材料清单**（V1.5）：渠道/话术详情增加「所需材料清单 + 自检表」，按场景给出必带/建议材料，解决"知道怎么投诉却不知准备什么"的痛点。
