## 1. 项目背景

### 1.1 业务背景

三份权威维权资料（《官方投诉维权渠道大全》《生活投诉渠道大全》《群众诉求官方平台汇总》）合计超 11 万字、260+ 表格，覆盖 51 个生活领域、109+ 行业投诉渠道、16 个高层级诉求平台。信息密度极高，但存在结构性体验问题：

| 痛点 | 具体表现 | 用户损失 |
|------|----------|----------|
| 检索困难 | 长文档无结构化检索，需逐页翻找 | 遇到问题时无法快速定位对口渠道 |
| 信息分散 | 电话、网址、话术、流程分散在多处 | 需要跨章节拼凑完整维权方案 |
| 时效风险 | 热线频繁整合（12369→12345、12358→12315 等 12 条已变更） | 拨打失效号码，延误维权时机 |
| 专业门槛 | 话术需引用法律条文，普通用户不会写 | 投诉因表述不规范被不予受理或调解无果 |
| 流程缺失 | 投诉后不知多久该有结果、超期怎么办 | 投诉石沉大海后不知如何升级 |

### 1.2 产品机会

维权是全民高频刚需（全国 12315 年受理超 3000 万件、12345 年受理超 1 亿件），但市场缺乏一款覆盖「找渠道 → 写话术 → 跟流程」全链路的工具型产品。现有竞品多为单部门视角或纯电话簿，存在明确产品空白。

### 1.3 文档目的与边界

本文档定义「我不能被欺负」v1.1.0 的完整产品需求，作为设计、研发、测试的唯一依据；同时在数据模型、技术架构、功能布局上为 V2.0（AI 智能问答 + 投诉进度管理）、V2.5（渠道效力 + 多城市）、V3.0（平台化）预留扩展接口，避免未来重构。

**合规边界**（贯穿全文档）：本产品为**信息查询工具**，不代理、不协助、不参与任何投诉或举报行为，不代用户向任何机构提交材料；倡导依法理性维权，鼓励优先通过企业官方客服、内部举报或反馈渠道协商解决纠纷；虚假、恶意投诉由用户自行承担法律责任。

## 2. 产品目标与范围

### 2.1 产品定位

**一句话定位**：输入关键词，秒出投诉电话、网址、话术与流程的随身维权工具箱。

**核心价值主张**：
- **找得到**：122 条官方渠道结构化入库，关键词搜索直达
- **用得上**：19 套高频场景话术（电话版 + 书面版），一键复制即用
- **走得对**：每个渠道标注监管部门、受理范围、前置条件，避免找错门
- **跟得住**：投诉跟进时间表提示每个节点的行动与升级路径

### 2.2 目标与度量

| 维度 | 目标值 | 度量方式 |
|------|--------|----------|
| 内容覆盖 | 122 行业渠道 + 18 高层级平台 + 19 话术 + 90 法规 100% 收录 | 数据录入核对清单 |
| 搜索体验 | 搜索响应 < 500ms，首条命中率 ≥ 80% | 内部回归用例（50 个典型 query） |
| 核心路径 | 搜索 → 查看渠道 → 复制话术 ≤ 3 次点击 | 交互走查 |
| 技术指标 | 冷启动 < 2s，主包体积 < 1MB | 性能测试 |
| 上线目标 | 微信小程序审核一次通过 | 审核结果 |

**北极星指标**：用户从「描述问题」到「复制可用话术」的中位耗时（目标 ≤ 30s）。

### 2.3 范围定义

#### 2.3.1 In Scope（本期做）

| 模块 | 功能点 | 优先级 |
|------|--------|--------|
| 搜索 | 关键词全文检索、搜索联想、热门搜索词、搜索历史 | P0 |
| 渠道详情 | 渠道信息展示、电话拨打、网址复制、收藏 | P0 |
| 分类浏览 | 五大类 + 二级分类树浏览、渠道卡片列表 | P0 |
| 话术模板 | 19 个场景话术（电话版 + 书面版）、一键复制、占位符填写 | P0 |
| 通用投诉信 | 结构化通用模板、占位符填写、一键复制 | P1 |
| 收藏 | 收藏渠道/话术、本地存储、收藏分组 | P1 |
| 工具箱 | 跟进时间表、热线变更速查、企业查询指引、关于页 | P1 |
| 紧急入口 | 110/119/120/96110 一键拨打（二次确认） | P0 |

| 证据管理 | V2.0 | evidence 表结构定义；话术详情预留「添加证据」入口（默认隐藏） |
| 话术定制生成 | V2.0 | script 表预留 script_type（template/ai_generated/custom）字段 |
| 效力评级可视化 | V2.0 | channel 表预留 effect_rating、response_speed、penalty_power 字段 |

### 2.4 与远景规划的衔接原则

1. **数据模型先行**：所有 V2.0/V2.5/V3.0 涉及的核心数据表，在本期即完成结构定义并写入数据字典，建表但不启用业务逻辑。
2. **扩展字段兜底**：每张核心业务表预留 `ext`（JSON 类型）字段，未来新增属性无需改表结构。
3. **接口抽象**：数据访问层按 Repository + Service 两层抽象，本期用本地实现，未来迁移后端仅替换实现类。
4. **配置化运营**：搜索权重、热门搜索词、分类配置、功能开关均放入配置层，运营可动态调整，无需发版。
5. **页面占位**：未来功能入口在页面布局中预留（默认隐藏），上线时仅需取消隐藏 + 联调，无需改版。

## 3. 用户与场景

### 3.1 目标用户画像

| 用户类型 | 人口特征 | 核心诉求 | 技术熟练度 | 使用频率 |
|----------|----------|----------|------------|----------|
| 普通消费者 | 20-45 岁，有网购/线下消费经历 | 快速找到对口投诉渠道和话术 | 中 | 低频 |
| 职场劳动者 | 22-50 岁，在职/离职 | 欠薪、社保、公积金、劳动仲裁路径 | 中 | 低频 |
| 业主/租户 | 25-50 岁，有房产或租房 | 物业不作为、乱收费、房屋质量 | 中低 | 中频 |
| 金融消费者 | 25-55 岁，有银行/保险/证券业务 | 销售误导、乱收费、理赔纠纷 | 中 | 低频 |
| 政务诉求者 | 30-60 岁，与政府部门打过交道 | 基层不作为、需要上级督办 | 中低 | 低频 |
| 中老年用户 | 50 岁+，智能手机基础操作 | 大字、大按钮、步骤清晰 | 低 | 低频 |

### 3.2 典型场景

- **场景 A（找渠道）**：消费者网购到翻新机，输入「淘宝 翻新机 不退」，系统提取关键词 → 推荐 12315/平台内部投诉路径 → 展示电话与书面话术。
- **场景 B（跟流程）**：用户已向企业投诉满 7 日无果，工具箱「跟进时间表」提示升级至邮政申诉（12305）的节点与前置条件。
- **场景 C（紧急）**：遭遇诈骗，紧急入口一键拨打 96110（二次确认防误触）。

### 3.3 用户旅程（核心路径）

```
遇到问题 → 首页搜索/分类 → 关键词匹配 → 场景选项卡 → 渠道详情
         → 复制话术（电话版照念/书面版复制） → 拨打/提交 → 工具箱跟进
```

## 5. 功能需求详述

> 每条需求含：功能描述、优先级（P0/P1/P2）、验收标准（Acceptance Criteria）、埋点。

### 5.1 搜索（P0）

**功能描述**：产品核心功能，支持关键词全文检索、实时联想、分类筛选、关键词高亮。本期采用本地索引方案，无需后端。

**验收标准**：
- AC-搜索-01：输入关键词后结果页 ≤ 500ms 渲染（内部基准 avg 0.42ms，量级无忧）。
- AC-搜索-02：支持拼音搜索、错别字纠正、同义词典（469 条）。
- AC-搜索-03：首条命中率 ≥ 80%（50 个典型 query 回归）。
- AC-搜索-04：无结果时展示引导页（分类入口 + 热门词），不报错。

**搜索策略**：
- 索引构建（启动异步，< 200ms）：渠道名称、投诉电话、适用范围、标签、上级监管部门。
- 匹配优先级：P1 名称精确 → P2 标签精确 → P3 电话精确 → P4 适用范围模糊 → P5 话术场景。
- 排序：最终得分 = 匹配优先级权重×100 + 热度权重(hot_level 1-5)×10 + 文本相似度。
- 同义词典（运营可扩展）：丢了/弄丢→丢失；坑人/骗人→误导/欺诈；乱收费→违规收费/价格违法；欠薪/不发工资→拖欠工资/欠薪。

**业务规则**：
- BR-S-001：搜索不区分大小写，支持中英文数字混合。
- BR-S-002：搜索历史本地存储最多 20 条，可单条删除或全部清除。
- BR-S-003：结果分页加载（每页 20 条），代码按分页实现。
- BR-S-004：同义词与权重在 `app_config.json` 配置，可动态调整。
- BR-S-005：搜索日志本地匿名记录（仅 query + 时间），V2.0 可上传优化。

**异常处理**：
- EX-S-001：索引构建失败 → 降级为字符串包含匹配，保证可用。
- EX-S-002：搜索超时（> 2s）→ 提示「搜索超时，请重试」。
- EX-S-003：无结果 → 引导页，不报错。

**埋点**：search_submit / search_suggest_click / search_result_view / search_result_click / search_tab_click / search_no_result / search_history_clear。

### 5.2 渠道详情（P0）

**页面结构**：顶部导航（返回 + 名称 + 收藏）、基本信息卡（名称/电话/网址/监管部门）、适用范围卡、前置条件卡、法律依据卡、实用提示卡、关联话术卡、信息来源（验证日期 + 来源）。

**验收标准**：
- AC-渠道-01：电话点击触发 `wx.makePhoneCall`，网址点击复制并提示。
- AC-渠道-02：字段为空时对应卡片自动隐藏（无空态占位）。
- AC-渠道-03：收藏状态本地持久化，列表实时同步。

### 5.3 分类浏览（P0）

- 五大分类 + 二级分类树；空分类自动隐藏。
- 渠道卡片列表，点击进入详情。

### 5.4 话术模板（P0）

- 19 套场景话术（电话版 + 书面版），一键复制。
- 占位符（【姓名】【电话】【金额】【身份证后四位】等）支持小程序内填写后生成个性化话术。
- 关联渠道展示，形成「话术 → 渠道」闭环。

### 5.5 收藏与历史（P1）

- 收藏渠道/话术，本地存储，支持自定义分组（重命名/排序/批量移动）。
- 浏览历史、搜索历史本地记录，便于回查。

### 5.6 工具箱（P1）

- 跟进时间表（静态，按渠道提示升级节点与前置条件）。
- 热线整合变更速查（12 条已变更热线对照）。
- 企业查询指引（鼓励优先企业内部/官方客服渠道）。
- 关于页（版本、数据规模、合规声明）。

### 5.7 紧急入口（P0）

- 110/119/120/96110 一键拨打，二次确认防误触。

## 7. 技术方案

> 详细设计见《技术设计文档 TDD》。本节给出产品侧需关注的关键结论。

- **运行环境**：微信小程序原生，JavaScript（ES6+），WXSS + Flex。
- **数据架构**：轻量索引（56KB 启动）+ 按需分片（60KB/片），单文件 ≤ 152KB，远低于 500KB 限制，支持扩展至 2000+ 条。
- **离线可用**：全部核心功能本地运行，无网络可用。
- **隐私合规**：本期不收集任何个人信息（无用户 ID、手机号、位置），无 UGC 内容，内容均来自政府公开渠道。
- **性能预算**：冷启动 < 2s，搜索 < 500ms，主包 < 1MB。
- **AI 接入**：架构预留 AIService 抽象层，开发者可自选厂商/协议/模型，本期默认关闭。
