## 1. 项目背景与问题

### 1.1 业务背景

三份权威维权资料（《官方投诉维权渠道大全》《生活维权渠道大全》《群众诉求官方平台汇总》）合计超 11 万字、260+ 表格，覆盖 51 个生活领域、109+ 行业维权渠道、16 个高层级诉求平台。信息密度极高，但存在结构性体验问题：

| 痛点层级 | 具体表现 | 用户损失 |
|----------|----------|----------|
| 检索困难 | 长文档无结构化检索，需逐页翻找 | 遇到问题时无法快速定位对口渠道 |
| 信息分散 | 电话、网址、话术、流程分散在多处 | 需要跨章节拼凑完整维权方案 |
| 时效风险 | 热线频繁整合（12369→12345、12358→12315 等 12 条已变更） | 拨打失效号码，延误维权时机 |
| 专业门槛 | 话术需引用法律条文，普通用户不会写 | 投诉因表述不规范被不予受理或调解无果 |
| 流程缺失 | 投诉后不知多久该有结果、超期怎么办 | 投诉石沉大海后不知如何升级 |

### 1.2 市场机会与量化依据

- **高频刚需**：全国 12315 年受理超 3000 万件、12345 年受理超 1 亿件，维权是全民级、跨年龄层的高频需求。
- **市场空白**：现有竞品多为单部门视角或纯电话簿，缺乏覆盖「**找渠道 → 写话术 → 跟流程**」全链路的工具型产品。
- **政策红利**：国务院《优化营商环境条例》、12345 热线整合等，使官方渠道检索与话术规范化具备持续需求。

### 1.3 合规边界（贯穿全文档，最高优先级）

> 本产品为**信息查询工具**，不代理、不协助、不参与任何投诉或举报行为，不代用户向任何机构提交材料；倡导依法理性维权，鼓励优先通过企业官方客服、内部举报或反馈渠道协商解决纠纷；虚假、恶意投诉由用户自行承担法律责任。

本约束为产品不可逾越红线，所有功能设计、文案、埋点均不得突破（详见 TDD §7、备案信息备注）。

## 2. 产品目标与非目标

### 2.1 产品定位

**一句话定位**：输入关键词，秒出投诉电话、网址、话术与流程的随身维权工具箱。

**核心价值主张**：

- **找得到**：122 条官方渠道结构化入库，关键词搜索直达对口部门。
- **用得上**：19 套高频场景话术（电话版 + 书面版），一键复制即用。
- **走得对**：每个渠道标注监管部门、受理范围、前置条件，避免找错门。
- **跟得住**：投诉跟进时间表提示每个节点的行动与升级路径。

### 2.2 目标（Goals）

| 编号 | 目标 | 度量方式 | 目标值 |
|------|------|----------|--------|
| G1 | 内容完整性 | 数据录入核对清单 | 122 渠道 / 18 平台 / 19 话术 / 90 法规 100% 收录 |
| G2 | 搜索体验 | 50 个典型 query 回归 | 搜索响应 < 500ms，首条命中率 ≥ 80% |
| G3 | 核心路径效率 | 交互走查 | 搜索 → 查看渠道 → 复制话术 ≤ 3 次点击 |
| G4 | 性能 | 真机性能测试 | 冷启动 < 2s，主包体积 < 1MB |
| G5 | 合规通过 | 微信审核结果 | 一次通过，无合规驳回 |
| G6 | 北极星体验 | 埋点中位值 | 描述问题 → 复制可用话术中位耗时 ≤ 30s |

### 2.3 非目标（Non-Goals，本期明确不做）

| 编号 | 非目标 | 说明 |
|------|--------|------|
| NG1 | 不代理 / 代提交投诉 | 仅信息展示，不向任何机构提交材料 |
| NG2 | 不做用户生成内容（UGC） | 无发帖、评论、点赞等用户自行发布的内容 |
| NG3 | 不收集个人信息 | 无注册登录、无手机号 / 位置 / openid 收集 |
| NG4 | 不接入后端 / AI 推理 | 当前纯本地，V2.0 再引入 |
| NG5 | 不做多端发布 | 当前仅微信小程序，V3.0 评估 |

> 非目标由国务院监管边界与团队最小可行原则共同决定，避免范围蔓延（scope creep）。详见 §9 范围管理。

### 2.4 北极星指标与护栏指标

- **北极星指标**：用户从「描述问题」到「复制可用话术」的中位耗时（目标 ≤ 30s）。
- **护栏指标（不可牺牲）**：
  - 合规红线零触碰（不代投诉、不收个人信息）；
  - 离线可用率 100%（无网络时核心功能全部可用）；
  - 冷启动 < 2s（性能基线不可破）。

## 3. 用户与场景

### 3.1 目标用户画像（Persona）

| 用户类型 | 人口特征 | 核心诉求 | 技术熟练度 | 使用频率 |
|----------|----------|----------|------------|----------|
| 普通消费者 | 20-45 岁，有网购 / 线下消费经历 | 快速找到对口维权渠道和话术 | 中 | 低频 |
| 职场劳动者 | 22-50 岁，在职 / 离职 | 欠薪、社保、公积金、劳动仲裁路径 | 中 | 低频 |
| 业主 / 租户 | 25-50 岁，有房产或租房 | 物业不作为、乱收费、房屋质量 | 中低 | 中频 |
| 金融消费者 | 25-55 岁，有银行 / 保险 / 证券业务 | 销售误导、乱收费、理赔纠纷 | 中 | 低频 |
| 政务诉求者 | 30-60 岁，与政府部门打过交道 | 基层不作为、需要上级督办 | 中低 | 低频 |
| 中老年用户 | 50 岁+，智能手机基础操作 | 大字、大按钮、步骤清晰 | 低 | 低频 |

### 3.2 作业待办（JTBD）

- **JTBD-1**：当我买到问题商品时，我要快速找到对口投诉电话与标准话术，以便依法维权不踩坑。
- **JTBD-2**：当我投诉久无回应时，我要知道何时、向哪一级升级，以便推进而非石沉大海。
- **JTBD-3**：当我遇紧急情况时，我要一键拨打正确紧急号码，以便及时求助。

### 3.3 典型场景

- **场景 A（找渠道）**：消费者网购到翻新机，输入「淘宝 翻新机 不退」，系统提取关键词 → 推荐 12315 / 平台内部投诉路径 → 展示电话与书面话术。
- **场景 B（跟流程）**：用户已向企业投诉满 7 日无果，工具箱「跟进时间表」提示升级至邮政申诉（12305）的节点与前置条件。
- **场景 C（紧急）**：遭遇诈骗，紧急入口一键拨打 96110（二次确认防误触）。

### 3.4 用户旅程（核心路径）

```
遇到问题 → 首页搜索/分类 → 关键词提取 → 场景选项卡 → 渠道详情
         → 复制话术（电话版照念 / 书面版复制） → 拨打/提交 → 工具箱跟进
```

### 3.5 无障碍与包容性设计

- 遵循微信小程序无障碍规范：语义化 `aria-*`、字号 ≥ 基础 16px 且支持系统字体放大。
- 大按钮（点击区 ≥ 44×44pt）、高对比配色、电话拨打主操作高亮绿色。
- 适老化：中老年用户路径 ≤ 3 步可达核心结果。

## 4. 产品原则与设计准则

1. **合法合规为先**：任何功能不得突破信息工具定位与备案边界。
2. **零成本离线可用**：无网络、无 API 费用时核心功能全部可用。
3. **可解释可信**：搜索结果展示匹配关键词，渠道标注验证日期与来源，可溯源。
4. **渐进式演进**：数据模型与架构提前预留 V2.0/V3.0 接口，避免未来推倒重来。
5. **配置化运营**：搜索权重、热门词、功能开关配置化，动态调整免发版。
6. **普惠易用**：面向全年龄段，大字号、大按钮、步骤清晰。

- 底部 Tab：首页 / 分类 / 话术 / 我的（4 个主入口）。
- 二级页：搜索结果、渠道详情、话术详情、工具箱、关于。
- 紧急入口全局可达（二次确认），不依赖页面层级。

### 5.3 扩展性设计

- 功能开关（`feature_flag`）控制 V2.0+ 入口显隐，本期全部关闭。
- 数据字典预留 V2.0/V2.5/V3.0 扩展字段，详见 §8.2。
- 搜索 / 数据访问层接口化，后端迁移对上层零改动（详见 TDD §3/§4）。

### 5.4 与远景规划的衔接原则

1. **数据模型先行**：所有 V2.0/V2.5/V3.0 核心数据表，本期即完成结构定义并写入数据字典，建表但不启用业务逻辑。
2. **扩展字段兜底**：每张核心业务表预留 `ext`（JSON 类型），未来新增属性无需改表。
3. **接口抽象**：数据访问层按 Repository + Service 两层抽象，本期本地实现，未来仅替换实现类。
4. **配置化运营**：搜索权重、热门词、分类、功能开关均入配置层，运营可动态调整。
5. **页面占位**：未来功能入口在页面布局中预留（默认隐藏），上线仅需取消隐藏 + 联调。

## 6. 功能需求详述

> 格式：每条需求含 **功能描述 / 优先级（P0/P1/P2）/ 用户故事与验收标准（AC）/ 埋点**，AC 采用 BDD 三段式（Given / When / Then）。

### 6.1 搜索（P0）

**功能描述**：产品核心功能，支持关键词全文检索、实时联想、分类筛选、关键词高亮。本期采用本地索引方案，无需后端。

**用户故事**：作为普通消费者，我希望输入自然语言就能得到对口渠道，以便无需懂专业术语也能维权。

**验收标准**：

- **AC-搜索-01**：*Given* 用户输入关键词，*When* 提交搜索，*Then* 结果页在 500ms 内渲染（内部基准 avg 0.42ms，量级无忧）。
- **AC-搜索-02**：*Given* 用户输入拼音或错别字，*When* 提交，*Then* 经同义词典（469 条）仍命中正确场景。
- **AC-搜索-03**：*Given* 50 个典型 query 回归集，*When* 全量执行，*Then* 首条命中率 ≥ 80%。
- **AC-搜索-04**：*Given* 无结果，*When* 展示，*Then* 引导页（分类入口 + 热门词）且不报错。

**搜索策略**：

- 索引构建（启动异步，< 200ms）：渠道名称、投诉电话、适用范围、标签、上级监管部门。
- 匹配优先级：P1 名称精确 → P2 标签精确 → P3 电话精确 → P4 适用范围模糊 → P5 话术场景。
- 排序：最终得分 = 匹配优先级权重×100 + 热度权重(`hot_level` 1-5)×10 + 文本相似度。

**业务规则**：

- BR-S-001：搜索不区分大小写，支持中英文数字混合。
- BR-S-002：搜索历史本地存储最多 20 条，可单条删除或全部清除。
- BR-S-003：结果分页加载（每页 20 条）。
- BR-S-004：同义词与权重在 `app_config.json` 配置，可动态调整。

**异常处理**：

- EX-S-001：索引构建失败 → 降级为字符串包含匹配，保证可用。
- EX-S-002：搜索超时（> 2s）→ 提示「搜索超时，请重试」。
- EX-S-003：无结果 → 引导页，不报错。

**埋点**：`search_submit` / `search_suggest_click` / `search_result_view` / `search_result_click` / `search_tab_click` / `search_no_result` / `search_history_clear`。

### 6.2 渠道详情（P0）

**页面结构**：顶部导航（返回 + 名称 + 收藏）、基本信息卡（名称 / 电话 / 网址 / 监管部门）、适用范围卡、前置条件卡、法律依据卡、实用提示卡、关联话术卡、信息来源（验证日期 + 来源）。

**验收标准**：

- **AC-渠道-01**：*Given* 用户查看渠道详情，*When* 点击电话，*Then* 触发 `wx.makePhoneCall`；点击网址，*Then* 复制并提示。
- **AC-渠道-02**：*Given* 某字段为空，*When* 渲染，*Then* 该卡片自动隐藏（无空态占位）。
- **AC-渠道-03**：*Given* 用户收藏，*When* 状态变更，*Then* 本地持久化且列表实时同步。

### 6.3 分类浏览（P0）

- 五大分类 + 二级分类树；空分类自动隐藏。
- 渠道卡片列表，点击进入详情。

### 6.4 话术模板（P0）

- 19 套场景话术（电话版 + 书面版），一键复制。
- 占位符（【姓名】【电话】【金额】【身份证后四位】等）支持小程序内填写后生成个性化话术。
- 关联渠道展示，形成「话术 → 渠道」闭环。

**验收标准**：

- **AC-话术-01**：*Given* 用户选择话术，*When* 点击复制，*Then* 写入剪贴板并 Toast 提示成功。
- **AC-话术-02**：*Given* 占位符未填，*When* 复制，*Then* 保留【】占位符原文，不报错。

### 6.5 收藏与历史（P1）

- 收藏渠道 / 话术，本地存储，支持自定义分组（重命名 / 排序 / 批量移动）。
- 浏览历史、搜索历史本地记录，便于回查。

### 6.6 工具箱（P1）

- 跟进时间表（静态，按渠道提示升级节点与前置条件）。
- 热线整合变更速查（12 条已变更热线对照）。
- 企业查询指引（鼓励优先企业内部 / 官方客服渠道）。
- 关于页（版本、数据规模、合规声明）。

### 6.7 紧急入口（P0）

- 110/119/120/96110 一键拨打，二次确认防误触。

**验收标准**：

- **AC-紧急-01**：*Given* 用户点击紧急号码，*When* 触发，*Then* 弹出二次确认；*When* 确认，*Then* 才拨打。

### 6.8 通用投诉信（P1）

- 结构化通用模板、占位符填写、一键复制。

## 7. 非功能需求（NFR）

### 9.3 短期规划（V1.5 体验完善版）

> 依据用户反馈：当前用户已能"找到维权渠道、照着话术投诉"，但仍有两处断点——（1）投诉路径仅覆盖**政府部门投诉、法律渠道、监管部门投诉**三类，缺少舆论监督性质的**媒体曝光**路径；（2）用户普遍"知道怎么投诉，却不知道投诉需要准备哪些材料"。两项均纳入 V1.5 短期规划，属数据/内容侧增强，无需改架构。

| 功能 | 计划版本 | 优先级 | 说明 |
|------|----------|--------|------|
| 媒体曝光路径 | V1.5 | P1 | 新增第四条维权路径「媒体曝光」（舆论监督/社会监督），与现有三类并列 |
| 投诉所需材料清单 | V1.5 | P1 | 渠道/话术详情增加「所需材料清单 + 自检表」，按场景给出材料 |

#### 9.3.1 媒体曝光路径（第四条投诉路径）

- **定位**：媒体曝光属**舆论监督/社会监督**路径，是独立于「企业投诉 → 监管投诉 → 法律途径」之外的另一条**完全独立、可并行**的维权路径，非官方受理渠道、不替代行政/司法/监管程序。媒体本身不能解决问题，最终解决的仍是相关监管部门和司法机关；法律始终是维护权益的最后兜底，应当相信法治、依靠法治。
- **与官方路径的关系（双轨并行）**：媒体曝光与官方投诉路径并行存在、可同时启动、相互配合，不存在固定先后顺序；官方路径负责依法调查处理，媒体路径负责舆论监督推动重视。两者不能相互替代。
- **适用场景（尤其适合启动并行路径）**：①官方渠道久拖不决、超法定办理期限；②涉地方保护主义、敷衍了事；③被投诉方推诿踢皮球、拒不处理；④事件具公共性/典型性、涉群体利益；⑤具新闻价值的典型侵权事件；⑥涉公共利益、群体性权益受损；⑦能引起大众反思、推动行业进步的普遍性问题。
- **平台形态（工具内呈现）**：渠道/话术增加 `media` 维度，给出可投送媒体类型（主流媒体爆料台/民生栏目、消协/消保委曝光入口、政务新媒体）、投稿方式模板与材料清单；主流媒体如有抖音/B 站官方账号应直接贴出并允许复制；标注"以官方/司法结论为准"。
- **合规边界（严格）**：必须基于真实、完整事实与证据，严禁夸大、捏造、断章取义；不得泄露商业秘密与个人隐私（含未成年人信息）；不得侮辱、诽谤、人肉搜索；通过个人账号曝光须注明"据本人掌握证据如实陈述，以官方调查为准"。
- **数据模型**：`channel.path_type` 枚举新增 `media`；新增媒体曝光渠道/话术集合。

#### 9.3.2 投诉所需材料清单（材料自检）

- **痛点**：用户"知道怎么投诉"，但"不知道投诉需要哪些材料"，导致证据不全、流程反复。
- **功能**：渠道详情与话术详情增加「所需材料清单」，并提供勾选式**自检表**，提交前提示缺项；与 V2.0 证据管理衔接。
- **通用材料（多数投诉必备）**：①身份与关系证明；②交易与合同凭证（订单/支付/合同/发票）；③沟通记录（聊天/通话录音/邮件）；④侵权证据（照片/视频/质检报告/录屏/物流单）；⑤时间线说明；⑥诉求与损失证明。
- **分场景示例**：消费投诉（12315）需订单+支付+商品问题证据+协商记录；劳动纠纷需劳动合同+工资流水+考勤+解除通知+社保记录；物业需合同+缴费+报修记录+现场照片；金融消费需合同+营销页截图+扣费流水+销售录音。
- **数据模型**：`channel.materials` 为 JSON 数组（材料名 + 必填/建议 + 说明），关联话术/渠道详情展示。
