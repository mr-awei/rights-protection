# 知识库结构说明（AI 接入用）

> 本文定义本项目的知识库 schema，供后续接入 AI（RAG / 向量检索 / 大模型）时直接消费数据，无需重新梳理。
> **重要：本方案只对数据做"导出层"改造，不改变小程序运行时存储，因此对用户功能、包体积、离线能力零影响。**

## 一、数据流水线（已改造：Markdown 作为唯一数据源）

```
kb/*.md（唯一数据源 SSOT，人工维护）
    │  node scripts/kb-build.js --write
    ▼
miniprogram/data/*.js + miniprogram/detail/data/*.js（运行时数据，自动生成，勿手工编辑）
    │  node scripts/export-kb.js
    ▼
data/knowledge-base.json（AI 知识库，不参与打包）

source/*.docx → 降级为原始素材归档，不再是维护主体

- **唯一数据源**：`kb/` 下 7 个 Markdown（按一级分类聚合（详见 [`kb/README.md`](../kb/README.md）

- **运行时**：JS 模块，**由脚本生成**，不要手工编辑

- **知识库**：`data/knowledge-base.json`，一键生成，**不进小程序包**

> 改造收益：消除 docx / js / json 三处重复维护——以前改一处要同步三处（已踩过坑：doc1 写 51 个领域、doc3 写 50 个）。现在只改 md，其余全部自动生成，`kb-build.js` 会做一致性校验。

> **详细说明见 [`kb/README.md`](../kb/README.md)。**

导出命令：

```bash
node scripts/export-kb.js
```

## 二、文件结构

`data/knowledge-base.json`：

```jsonc
{
  "schema_version": "1.0.0",
  "generated_at": "ISO 时间戳",
  "source": "血缘说明",
  "stats": { "channels": 122, "scripts": 19, "laws": 90, "relations": 50 },
  "entities": [ /* 渠道 + 话术 + 法条，统一实体数组 */ ],
  "relations": [ /* 显式关系表 */ ],
  "categories": {
    "category_l1": [],      // 5 个一级分类
    "category_user": [],    // 13 个用户视角分类
    "issue_types": []       // 7 种问题类型
  }
}
```

## 三、实体 Schema

实体用 `type` 字段区分，所有实体共用 `id` 主键。

### channel（维权渠道，122 条）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 主键，如 `ch_001` |
| `name` | string | 渠道名称 |
| `phone` | string | 投诉电话 |
| `website` | string | 官方网址 |
| `regulator` | string | 上级监管部门 |
| `scope` | string | 适用范围 |
| `precondition` | string | 前置条件（如"先向企业投诉满 7 日"） |
| `tips` | string | 实用提示 |
| `category_l1` | string | 一级分类（5 个之一） |
| `category_l2` | string | 二级分类 |
| `category_user` | string | 用户视角分类（13 个之一） |
| `issue_types` | string[] | 问题类型，如 `overcharge` / `inaction` |
| `tags` | string[] | 搜索标签 |
| `channel_type` | string | `hotline` / `platform` / `official` 等 |
| `hot_level` | number | 热度权重 1–5 |

### script（投诉话术，19 条）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 主键，如 `sc_001` |
| `scene_name` | string | 场景名 |
| `applicable` | string | 适用情况 |
| `category` | string | 场景分类 |
| `keywords` | string[] | 搜索关键词 |
| `is_general` | boolean | 是否通用话术 |
| `hot_level` | number | 热度 |
| `phone_script` | string | 电话版话术（含【】占位符） |
| `written_template` | string | 书面版话术（含【】占位符） |

### law（法律法规，90 条）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 主键，如 `law_001` |
| `name` | string | 法规名 |
| `full_name` | string | 全称 |
| `category` | string[] | 适用分类 |
| `article` | string | 完整正文（整篇法规文本） |
| `articles` | {no, content}[] | 按「第x条」切片后的条文数组 |
| `cited_by` | {type, id, name}[] | 反向引用：被哪些渠道/话术引用（含条文级 `law_id#条`） |

## 四、关系 Schema

| rel | 含义 | 现有条数 |
|---|---|---|
| `has_script` | 渠道 → 话术（渠道 `related_script_id`） | 33 |
| `belongs_to_channel` | 话术 → 渠道（话术 `related_channel_id`） | 17 |
| `cites_law` | 渠道/话术 → 法条（`law_ids`，可到条文级 `law_id#条`） | 已建立（话术正文自动提取《xx法》第x条，渠道合并显式+自动） |
| `cited_by` | 法条 → 渠道/话术（反向，含 `law_id#条`） | 已建立（由 cites_law 推导） |

## 五、注意事项与已知问题

1. **`law_ids` 格式不统一（已修正）**：历史数据里 `law_ids` 混杂了逗号分隔字符串（`"law_002,law_003"`）与数组两种写法。**知识库 `kb/` 已统一为数组**，`kb-build` 比对时会规范化兼容。> ⚠️ 早期版本曾误判"渠道→法条关系为 0"——那是因为当时读的是 `channels_index.js`（轻量索引，无 `law_ids`）。实际**122 条渠道全部带 `law_ids`**，完整数据在 `detail/data/channels_part_*.js`。
2. **法条已按条文切片**：`articles` 数组即「第x条」切片结果，RAG 可直接向量化 `articles` 而非整篇；完整正文在 `detail/data/laws.js` 与 `kb/laws/*.md`。
3. **搜索索引已接入并瘦身**：`miniprogram/detail/data/search_index.json`（BM25，~669KB）与 `suggest_trie.json`（Trie，~48KB）由 `scripts/build-search-index.js` 从 kb 生成并下沉 detail 分包（主包体积不增）；`detail/utils/search.js` 用 BM25 评分、`suggest` 用 Trie 前缀匹配。

## 六、AI 接入建议（分阶段）

| 阶段 | 动作 | 成本 | 风险 |
|---|---|---|---|
| **已完成** | 导出 `knowledge-base.json`，统一 schema + 关系表 | 极低 | 无 |
| **已完成** | 补 `cites_law` 关系（含条文级 law_id#条）、法条按 `articles` 切片；搜索索引 BM25/Trie 已接入 detail 分包 | 低 | 无 |
| 若要语义检索 | 对实体做 embedding（231 条，量很小），可本地预计算或服务端 | 中 | 包体 / 是否需后端 |
| 若要问答 | 引入大模型 + 向量库（需后端） | 高 | 隐私合规（用户查询内容敏感）、离线能力丧失 |

> ⚠️ 隐私提示：用户的查询内容本身就是"投诉某公司"这类敏感信息。**保持本地检索是当前产品的隐私优势**，上云端 AI 前须做匿名化与合规评估。

## 七、维护约定

- 改了 `kb/*.md` 后，先 `node scripts/kb-build.js --write` 重建运行时数据，再 `node scripts/build-search-index.js` 重建搜索索引（search_index.json / suggest_trie.json）；如需导出 AI 知识库改 `node scripts/export-kb.js`（注：其输出目标 `data/knowledge-base.json` 所在根目录 `data/` 已于 89b5c3b 删除，如需 AI 归档请改输出到 `kb/` 或他处）
- `schema_version` 变更时要同步更新本文档
- 新增实体类型需在 `entities` 里补 `type` 并在本文档登记字段
