# 知识库结构说明（AI 接入用）

> 本文定义本项目的知识库 schema，供后续接入 AI（RAG / 向量检索 / 大模型）时直接消费数据，无需重新梳理。
> **重要：本方案只对数据做"导出层"改造，不改变小程序运行时存储，因此对用户功能、包体积、离线能力零影响。**

## 一、数据流水线

```
source/*.docx（原始权威文档）
    │  人工维护
    ▼
miniprogram/data/*.js + miniprogram/detail/data/*.js（运行时数据，JS 模块）
    │  node scripts/export-kb.js
    ▼
data/knowledge-base.json（AI 知识库，不参与打包）
```

- **权威源**：`source/` 下三份 docx
- **运行时**：小程序 `require` 的 JS 模块（保持现状，不动）
- **知识库**：`data/knowledge-base.json`，由脚本一键生成，**不进小程序包**

导出命令：

```bash
node scripts/export-kb.js
```

## 二、文件结构

`data/knowledge-base.json`：

```jsonc
{
  "schema_version": "1.0.0",
  "generated_at": "ISO 时间戳",
  "source": "血缘说明",
  "stats": { "channels": 122, "scripts": 19, "laws": 90, "relations": 50 },
  "entities": [ /* 渠道 + 话术 + 法条，统一实体数组 */ ],
  "relations": [ /* 显式关系表 */ ],
  "categories": {
    "category_l1": [],      // 5 个一级分类
    "category_user": [],    // 13 个用户视角分类
    "issue_types": []       // 7 种问题类型
  }
}
```

## 三、实体 Schema

实体用 `type` 字段区分，所有实体共用 `id` 主键。

### channel（维权渠道，122 条）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 主键，如 `ch_001` |
| `name` | string | 渠道名称 |
| `phone` | string | 投诉电话 |
| `website` | string | 官方网址 |
| `regulator` | string | 上级监管部门 |
| `scope` | string | 适用范围 |
| `precondition` | string | 前置条件（如"先向企业投诉满 7 日"） |
| `tips` | string | 实用提示 |
| `category_l1` | string | 一级分类（5 个之一） |
| `category_l2` | string | 二级分类 |
| `category_user` | string | 用户视角分类（13 个之一） |
| `issue_types` | string[] | 问题类型，如 `overcharge` / `inaction` |
| `tags` | string[] | 搜索标签 |
| `channel_type` | string | `hotline` / `platform` / `official` 等 |
| `hot_level` | number | 热度权重 1–5 |

### script（投诉话术，19 条）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 主键，如 `sc_001` |
| `scene_name` | string | 场景名 |
| `applicable` | string | 适用情况 |
| `category` | string | 场景分类 |
| `keywords` | string[] | 搜索关键词 |
| `is_general` | boolean | 是否通用话术 |
| `hot_level` | number | 热度 |
| `phone_script` | string | 电话版话术（含【】占位符） |
| `written_template` | string | 书面版话术（含【】占位符） |

### law（法律法规，90 条）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 主键，如 `law_001` |
| `name` | string | 法规名 |
| `full_name` | string | 全称 |
| `category` | string[] | 适用分类 |
| `article_excerpt` | string | 条文摘要（前 300 字，完整条文回查 `detail/data/laws.js`） |

## 四、关系 Schema

| rel | 含义 | 现有条数 |
|---|---|---|
| `has_script` | 渠道 → 话术（渠道 `related_script_id`） | 33 |
| `belongs_to_channel` | 话术 → 渠道（话术 `related_channel_id`） | 17 |
| `cites_law` | 渠道 → 法条（`law_ids`） | **0（见下节缺口）** |

## 五、已知缺口

1. **`cites_law` 关系缺失**：渠道数据里没有 `law_ids` 字段，渠道与法条**目前没有建立关联**。要做 AI 法条推荐（"投诉 XX 该引用哪条法律"），需要先补这层关系（可从渠道的 `scope` / `tags` 与法条 `category` 做自动匹配，再人工核对）。
2. **法条只存摘要**：完整条文仍在 `detail/data/laws.js`（148KB），做 RAG 时建议按条文切片后再向量化，而不是整篇入库。
3. **索引未接入**：`data/search_index.json`（BM25，697KB）与 `data/suggest_trie.json`（Trie，400KB）已生成但**未被小程序引用**。若要接入需先瘦身——直接放入 detail 分包会让分包达到约 1.84MB（上限 2MB 的 90%），风险高。

## 六、AI 接入建议（分阶段）

| 阶段 | 动作 | 成本 | 风险 |
|---|---|---|---|
| **已完成** | 导出 `knowledge-base.json`，统一 schema + 关系表 | 极低 | 无 |
| 下一步 | 补 `cites_law` 关系、法条按条文切片 | 低 | 无 |
| 若要语义检索 | 对实体做 embedding（231 条，量很小），可本地预计算或服务端 | 中 | 包体 / 是否需后端 |
| 若要问答 | 引入大模型 + 向量库（需后端） | 高 | 隐私合规（用户查询内容敏感）、离线能力丧失 |

> ⚠️ 隐私提示：用户的查询内容本身就是"投诉某公司"这类敏感信息。**保持本地检索是当前产品的隐私优势**，上云端 AI 前须做匿名化与合规评估。

## 七、维护约定

- 改了 `miniprogram/data/*.js` 或 `source/*.docx` 后，重跑 `node scripts/export-kb.js` 更新知识库
- `schema_version` 变更时要同步更新本文档
- 新增实体类型需在 `entities` 里补 `type` 并在本文档登记字段
