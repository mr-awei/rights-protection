# 小程序备案信息备注（合规用途）

> 适用对象：微信小程序「我不能被欺负」（v1.5.3+）
> 用途：ICP 备案 / 平台类目报备「备注」字段填写内容（20–200 字）

---

## 一、审核反馈（2026-09-11）

| 修改字段 | 待完善原因 | 修改建议 |
| --- | --- | --- |
| 小程序备注 | 小程序备注不符合要求-个人小程序备注不符合要求 | 小程序备注不符合个人性质，不能涉及企业或经营性等情况，请修改为符合个人性质的备注或删除备注。 |

### 1.1 被拒原因分析

原备注为：

> ~~「我不能被欺负」为个人开发者制作的**生活服务类**信息查询工具，**提供**消费维权渠道、投诉话术及法律法规查询，帮助用户了解合法维权路径。不代理、不替代用户提交材料，不参与投诉举报，**不涉及企业经营或商业服务**。虚假、恶意投诉后果由用户自行承担。~~

其中以下表述容易被审核判定为「涉及企业或经营性」：

| 原表述 | 风险点 |
| --- | --- |
| 生活服务**类** | 带「服务提供方」色彩，易被归入服务经营属性 |
| **提供**……查询 | 「提供」是典型经营口吻动词 |
| 不涉及**企业经营**或**商业服务** | 虽是否定句，但直接命中「企业经营」「商业服务」关键词，机器初审往往按词命中而非按语义判断 |
| **不代理、不替代**用户提交材料 | 「代理 / 提交材料」易被联想为代办业务 |
| 个人开发者**制作** | 尚可，但缺少「独立/个人所有」的强化 |

**结论**：个人小程序的备注应当**只描述「个人独立开发 + 信息整理展示 + 仅供个人参考」**三件事，并且**连否定式都不要提及**「企业、经营、商业、服务、代理、收费」等词——否定句同样会被关键词命中。

---

## 二、修订后备注（推荐，可直接复制）

> 本小程序由个人开发者独立制作，用于整理公开的消费维权电话、投诉途径与法律法规条文，方便个人查询学习，仅作信息参考。

- 字数：约 55 字（满足 20–200 字限制）
- 关键词自检：仅出现「个人开发者、独立制作、整理、公开、查询、学习、参考」，无企业 / 经营 / 商业 / 服务 / 代理 / 收费类词汇

## 三、备选方案

### 方案 B（更短，约 43 字）

> 个人开发者独立制作的维权信息查询小程序，整理公开的投诉电话与法律法规，仅供个人学习参考。

### 方案 C（极简，约 26 字）

> 个人开发者独立制作的维权信息查询小程序，仅供个人学习参考。

### 方案 D（留空 / 删除备注）

审核建议中已明确「或删除备注」。若备案系统中「备注」为**非必填项**，直接留空或删除是最稳妥的做法；仅在系统强制要求填写时，才使用上面的方案 A / B。

## 四、统一自检清单（填备注前逐条核对）

- [ ] 是否出现「企业、公司、机构、组织、经营、商业、盈利、收费、付费」等词？（**含否定句**）
- [ ] 是否出现「服务、提供、代理、代办、受理、办理、承接」等经营口吻动词？
- [ ] 是否明确写出「个人开发者 / 个人所有 / 独立制作」？
- [ ] 是否说明内容来源为公开渠道、用途为个人查询学习？
- [ ] 是否出现「投诉、举报」等易被判定为代客受理的词？（本文案改用「投诉途径 / 投诉电话」描述信息本身，避免「代为投诉」的歧义）
- [ ] 字数是否在 20–200 字区间？

---

## 五、合规要点

- **名称一致**：名称「我不能被欺负」与备注中「维权信息查询」形成关联，使名称、内容、备注三者自洽。
- **个人性质**：明确「个人开发者独立制作」，不出现任何机构或经营主体表述。
- **纯信息属性**：只描述「整理、展示公开信息」，不描述任何形式的代办、受理、提交动作。
- **免责**：小程序内的免责声明页已完整承载「不代投诉、不代举报、虚假投诉自担责任」等内容，备注字段无需重复，避免关键词风险。
